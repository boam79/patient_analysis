**작성일**: 2026-07-11  
**역할**: Planner  
**상태**: 제안 (구현 전 승인 대기)  
**범위**: 시각·정보 구조·인터랙션 (기능 로직 변경 최소화)

## 1. 배경

병원 CRM은 분석·인증·관리자 기능이 v4.7까지 성숙했으나, UI는 shadcn 기본 토큰·카드 중첩·이모지 네비·랜딩 부재 상태로 남아 있습니다. 제품 가치(로컬 PHI 보호, 재방문·공간·전략 분석)가 첫 화면에서 드러나지 않습니다.

### 현재 실측 문제

| 영역 | 현황 | 문제 |
|------|------|------|
| 진입점 | `/` → `/dashboard/upload` 즉시 리다이렉트 | 브랜드·가치 전달 없음 |
| 토큰 | `globals.css` 흑백 primary, 기본 radius | 병원/분석 제품 정체성 없음 |
| 폰트 | Tailwind에 Pretendard 선언, 실제 로드 없음 | 시스템 폰트로 폴백 |
| 헤더 | 이모지 네비, 버전 `v4.5` 표기 | README(v4.7)와 불일치, 시각 잡음 |
| 대시보드 | KPI 카드 4 + 차트 카드 다수 중첩 | 밀도는 높은데 계층이 약함 |
| 로그인 | `bg-slate-50` + 중앙 Card | 범용 SaaS 템플릿 인상 |
| Admin | `bg-slate-900` 사이드바 + blue accent | 메인 앱과 디자인 언어 분리 |
| 유령 UI | `main-dashboard.tsx`, `bottom-tabs.tsx` 플레이스홀더 | 실제 페이지와 중복·혼란 |

## 2. 디자인 방향: **Harbor Clinical**

의료 분석 도구에 맞는 **신뢰·명료·차분한 해안(Harbor) 톤**. AI 기본 클리셰(퍼플 그라데이션, 크림+세리프+테라코타, 다크모드 기본, 글로우, pill 남발)는 배제합니다.

### 2.1 브랜드

- **제품명**: 병원 CRM (히어로·워드마크 수준, 네비 텍스트만으로 끝내지 않음)
- **한 줄 가치**: “방문 데이터로 재방문·지역·전략을 한눈에”
- **마크**: 기하학적 펄스/십자 모티프(이모지·스티커 배지 금지)

### 2.2 색 (CSS 변수)

```
--brand:        #0B6E6E   /* deep teal — primary CTA */
--brand-ink:    #0A2F2F   /* 거의 검정에 가까운 teal */
--surface:      #F3F6F7   /* cool mist */
--surface-2:    #E7EEF0
--ink:          #142126
--muted:        #5A6B72
--line:         #D0DBE0
--positive:     #1A8F6E   /* 기존 positive 계열 유지·정제 */
--warning:      #C47A12
--danger:       #C23B3B
--chart-1..5:   teal / slate / amber / soft coral / sage
```

배경은 단색 flat 금지 → mist 그라데이션 + 아주 옅은 도트/그리드 패턴.

### 2.3 타이포

| 역할 | 폰트 | 비고 |
|------|------|------|
| Display / 브랜드 | **SUITE** (또는 Pretendard Variable Bold) | next/font 또는 CDN 실로드 |
| Body | **Pretendard Variable** | 한글 본문 |
| Numeric / KPI | **IBM Plex Mono** 또는 tabular-nums Pretendard | 숫자 정렬 |

`Inter`/`Roboto`/`Arial`/system 기본 스택 의존 제거.

### 2.4 모션 (의도적 2–3개)

1. 랜딩 히어로: 브랜드·카피 fade-up (200–400ms)
2. 업로드 성공: 체크/진행 바 한 번만의 settle
3. 대시보드 KPI: 숫자 count-up 또는 opacity settle (과한 차트 애니메이션 금지)

## 3. 화면별 개편 요지

### 3.1 랜딩 (`/`) — 신규

첫 뷰포트 = **하나의 구성**:

- 풀블리드 비주얼 평면(지도/차트 실사용 분위기 사진 또는 CSS 기반 맵 실루엣 — inset 카드형 히어로 금지)
- 브랜드 워드마크 (히어로급)
- 헤드라인 1 + 짧은 문장 1
- CTA: `데이터 시작하기` → `/dashboard/upload`, 보조: `대시보드 보기`(데이터 있을 때)

히어로에 통계 스트립·일정·주소·프로모 칩·플로팅 배지 넣지 않음.  
섹션은 목적당 하나: (1) 왜 로컬 처리인가 (2) 4대 분석 축 (3) 시작 CTA.

### 3.2 앱 셸 (Header / Footer)

- 이모지 제거 → Lucide 아이콘 또는 텍스트만
- 활성 라우트 언더라인/teal 인디케이터
- 버전 배지 정리 (`v5.0` 또는 제거)
- 모바일: 햄버거/시트 네비
- Footer: 제작자·문의 유지, 시각적으로 더 얇고 브랜드 톤에 맞춤

### 3.3 업로드

- 드롭존을 페이지의 시각 앵커로 (카드 남발 축소)
- 단계 표시: 파일 선택 → 처리 → 완료 (한 흐름)
- 지오코딩 옵션은 보조 텍스트로 낮춤

### 3.4 대시보드 (대시보드이므로 카드 예외 허용, 단 중첩 축소)

- KPI: 테두리·그림자 없는 **메트릭 스트립** (카드 4개 나열 대신)
- 필터: sticky 바, 접기/펼치기
- 차트 영역: 섹션 타이틀 1 + 짧은 설명, 불필요한 Card-in-Card 제거
- 빈 상태: 업로드 CTA가 명확한 empty composition

### 3.5 로그인 / 제작자 로그인

- mist 배경 + 브랜드 워드마크 상단
- 폼은 상호작용 컨테이너로만 유지 (장식용 카드 느낌 축소)

### 3.6 Admin

- 메인과 동일 토큰 공유 (사이드바만 ink/teal 변형)
- blue-500 액센트 → brand teal
- “제작자 페이지” → 브랜드 하위 라벨 정리

### 3.7 정리

- 미사용 플레이스홀더 `main-dashboard.tsx`, `bottom-tabs.tsx` 삭제 또는 실제 페이지로 통합 여부 결정

## 6. 성공 정의 (전체)

1. 네비를 가려도 첫 화면이 **병원 CRM**으로 식별됨  
2. 퍼플/크림세리프/다크글로우 클리셰 없음  
3. 기존 분석·업로드·필터 기능 회귀 없음  
4. 모바일에서 주요 플로우 사용 가능

## 8. 승인 요청

구현은 **Executor 모드**에서 Phase 0부터 한 Task씩 진행합니다.

확인이 필요한 선택지:

1. **방향명 Harbor Clinical (teal mist)** 승인 여부 — 대안: 더 차가운 slate-clinical / 더 따뜻한 sage-clinical  
2. **랜딩 신설** vs 업로드를 브랜드화만 하고 `/` 리다이렉트 유지  
3. **Admin까지 동일 톤** vs 메인 앱만 우선  

승인 후 Executor에게 Phase 0 (D0.1)부터 지시해 주세요.
