## 1. 한 줄 요약

차트·분석 화면이 **너무 많고 겹칩니다**. 먼저 **가짜/죽은 것·중복을 줄이고**, 남는 핵심만 **필터·환자키·지도 모드**를 맞춰 고도화하는 편이 효과적입니다.

---

## 2. 현황 (실측)

| 영역 | 대략 규모 | 핵심 이슈 |
|------|-----------|-----------|
| 대시보드 | KPI + 차트 8종 + 테이블 | 테이블 재방문율 `Math.random()` **가짜값** |
| 차트 페이지 | 7종 | **필터 미적용**, 대시보드와 대량 중복 |
| 지도 | 탭 8 + LeafletMap | InteractiveMap과 **이중 구현**, 히트맵/클러스터 UI 미노출 |
| 전략 | 탭 14 + 경영 인사이트 | 시계열·유지·질병-수술이 **3~6중 중복** |
| 죽은 코드 | `OptimizedDiseaseChart` 등 | 미사용 컴포넌트·미렌더 import |

환자 식별이 화면마다 `name|address` vs `patient_id`로 갈라져 **같은 업로드에서도 수치가 어긋날 수 있음**.

## 3. 없어도 되는 것 (정리 권장)

우선순위 높은 순.

### A. 즉시 제거·수정 (신뢰성)

| 대상 | 이유 | 제안 |
|------|------|------|
| 대시보드 테이블 **재방문율 열** (`Math.random()`) | 가짜 지표 → 의사결정 오해 | 실제 계산 연결 **또는 열 삭제** |
| `OptimizedDiseaseChart` | 라우트에서 미사용 | 파일 삭제 |
| `disease-surgery-strategy`의 미사용 Scatter import | 죽은 코드 | import/코드 정리 |
| `BoxplotChart` 라벨 | 실제 박스플롯이 아님 (막대 근사) | 이름·설명을 「사분위 구간」으로 정정하거나 진짜 박스플롯으로 교체 |

### B. 중복이라 줄여도 되는 것 (IA 정리)

| 대상 | 이유 | 제안 |
|------|------|------|
| **`/dashboard/charts` 페이지 전체** | 대시보드와 Top질병·연령·월별·신규/재방문이 거의 동일, 필터도 없음 | **폐지 후 대시보드 탭으로 흡수**, 또는 필터 연동 후 「상세 차트」만 남김 |
| `TopDiseasesChart` | `InteractiveDiseaseChart`와 역할 중복 | 필터 연동 단일 컴포넌트로 통합 |
| 전략 **예측 분석** 탭 | 단순 이동평균, **계절성·예측**·고급 통계 STL과 겹침 | 계절성·예측으로 통합, 예측 탭 제거 |
| 전략 **시기별 트렌드** 중 월별 | 대시보드/차트 월별과 동일 계열 | 분기·요일·계절만 남기거나 대시보드로 링크 |
| 전략 **질병/수술 전략** 매트릭스성 UI | 대시보드 SurgeryMatrix + 차트 Heatmap + 연관분석과 3중 | **연관 분석(Lift)** 을 본체로, 전략 탭은 인사이트 문장 위주로 |
| 대시보드 임베드 지도 (markers only) | 지도 전용 페이지가 더 풍부 | 대시보드는 「지도로 이동」CTA만, 또는 동일 LeafletMap 재사용 |

### C. 유지하되 노출 축소 (고급 사용자용)

| 대상 | 이유 |
|------|------|
| 고급 통계 탭 (KM, k-means, PSI 등) | 가치 있으나 일반 운영자엔 과다 → 「고급」접기/권한 또는 맨 끝 유지 |
| 환자 여정 CSS 플로우 | Sankey 미완성, 유입/유지 탭과 겹침 → 유입/유지로 흡수 후보 |

## 4. 고도화할 것 (가치 높은 순)

### P0 — 정확성·일관성 (차트 추가보다 중요)

1. **환자 키 통일** (`patient-identity` 단일 규칙) — KPI·전략·지도 수치 일치  
2. **필터를 모든 분석 화면에 동일 적용** — 특히 charts 페이지(존치 시)  
3. **가짜 재방문율 제거/실계산**  
4. **지도 엔진 1개로 통합** + 히트맵·클러스터를 지도 페이지에 노출 (이미 코드 일부 존재)

### P1 — 핵심 차트 품질

| 차트 | 고도화 |
|------|--------|
| Top 질병 (인터랙티브) | 클릭 필터 유지 + 수술 Top와 토글 통합 |
| 월별 추세 / 신규·재방문 | 공통 훅 1개, brush로 기간 확대, 신뢰구간 옵션 |
| 지역 비교 | 지도 선택 ↔ 차트 연동 (brushing) |
| 재방문 속도 (`RetentionChart`) | RFM·코호트와 용어 통일, Wilson CI 표시 |
| 질병×수술 | 히트맵 1개 + Lift 오버레이 (연관분석 흡수) |
| 수술 산점도 | 대시보드 유일 강점 → 툴팁에 건수·필터 연동 강화 |

### P2 — 전략 탭 재편 (14 → ~7)

권장 정보구조:

1. 경영 요약 (Executive + ManagementInsights)  
2. 유입·유지 (Flow + RFM 핵심)  
3. 지역 시장  
4. 질병·수술·연관 (통합)  
5. 세그먼트  
6. 시계열·계절·예측 (통합)  
7. 이상 탐지 + (접기) 고급 통계  

코호트는 유입·유지 하위 또는 독립 유지(이미 Wilson CI 등 완성도 높음).

### P3 — 지도 (기존 제안서 잔여)

- 히트맵 / 클러스터 UI  
- (선택) 시간 슬라이더, hotspot — 범위 크면 후순위

## 5. 권장 로드맵 (작을수록 먼저)

### Phase R — 신뢰·정리 (최소 변경, 최대 효과)

| ID | Task | 성공 기준 |
|----|------|-----------|
| R1 | 테이블 가짜 재방문율 수정 또는 열 삭제 | `Math.random` 제거, 수치 재현 가능 |
| R2 | `OptimizedDiseaseChart` 삭제 | 빌드·참조 0 |
| R3 | Boxplot 라벨/설명 정정 | 사용자에게 오해 없는 명칭 |
| R4 | 환자 키 통일 점검 + 불일치 문서화/수정 | 동일 데이터에서 KPI≈전략 환자수 |

### Phase C — 중복 축소

| ID | Task | 성공 기준 |
|----|------|-----------|
| C1 | `/dashboard/charts` 폐지 **또는** 필터 연동+유일 차트만 잔류 | 네비·라우트 결정 반영 |
| C2 | Top 질병 컴포넌트 1개로 통합 | 중복 파일 제거 |
| C3 | 전략: 예측 탭 → 계절성·예측 병합 | 탭 수 감소, 기능 손실 없음 |
| C4 | 지도 컴포넌트 통합 + 히트맵/클러스터 노출 | 지도 페이지에서 모드 전환 가능 |

### Phase E — 고도화

| ID | Task | 성공 기준 |
|----|------|-----------|
| E1 | 월별 추세 공통 훅 + brush | 대시보드·전략이 동일 집계 |
| E2 | 질병×수술 히트맵 + Lift | 연관 탭과 매트릭스 중복 해소 |
| E3 | 전략 IA 7탭 재편 | 문서화된 탭 구조와 UI 일치 |
| E4 | 지역 차트↔지도 brushing | 클릭 시 양쪽 하이라이트 |
