# UI·메뉴(IA) 개선 제안서 v5.6

> **작성일**: 2026-07-21  
> **작성자**: Cloud Agent (Planner)  
> **기준**: `main` @ `0e6c924` (v5.5.0) · Harbor Clinical 토큰 유지  
> **범위**: 메인 앱 네비·대시보드 셸·전략 탭·Admin 콘솔 IA/레이아웃. **분석 로직·차트 라이브러리 비목표**.

---

## 요약

v5.0 Harbor Clinical로 **브랜드·토큰·랜딩**은 갖춰졌고, v5.5로 Admin **기능**도 성숙했다.  
남은 병목은 기능이 아니라 **정보 구조(메뉴 밀도)·셸 레이아웃·화면 간 톤 불일치**다.

| 영역 | 현재 | 핵심 문제 |
|------|------|-----------|
| 메인 헤더 | 대시보드 / 지도 / 전략 + 업로드 CTA | 업로드가 네비 밖·모바일에서 2차; 필터/샘플 상태 약함 |
| 대시보드 | 긴 단일 스크롤 + 카드 격자 | 섹션 앵커·시각 계층 약함, 카드 밀도 높음 |
| 전략 | 7탭 가로 TabsTrigger | 좁은 화면에서 탭 과밀·라벨 잘림 |
| Admin 사이드바 | **평탄 9항목** | 그룹 없음 → 스캔 비용 큼 |
| Admin 레이아웃 | Header 위 + Sidebar 옆 | 일반 어드민 셸과 어긋남, 모바일 사이드바 없음 |
| Admin vs 메인 | ink 사이드바 vs mist 헤더 | 의도적 구분이나 **내부 페이지**는 여전히 shadcn 기본 카드 나열 |

**권고 방향**: 메뉴 그룹화·Admin 셸 재배치 → 메인 네비 보강 → 대시보드/전략 스캔성 → (선택) 모션·빈상태.  
디자인 시스템(teal mist)은 **유지**하고, 퍼플/크림세리프/다크글로우 클리셰는 계속 배제.

## 1. 현황 실측

### 1.1 메인 앱 IA

```
/ 랜딩
└── Header: [병원 CRM] [대시보드] [지도 분석] [전략 분석] …… [데이터 업로드]
    ├── /dashboard          통합 대시보드 (필터+KPI+차트+지도+표)
    ├── /dashboard/map      지도 4탭
    ├── /dashboard/strategy 전략 7탭
    └── /dashboard/upload   (헤더 CTA만, 네비 항목 아님)
```

- Footer: 브랜드·제작자·메일 — 톤은 Harbor와 맞음.
- 업로드는 분석 플로우의 **입구**인데 네비 1급이 아님 → “데이터 없음” 사용자 경로가 CTA 의존.

### 1.2 Admin IA (현재 9개 평탄)

```
대시보드 → 사용자 → 통계 → 로그 → 에러 → 알림 → 모니터링 → 유지보수 → 감사
```

업무 멘탈모델과 불일치:
- **사람**: 사용자  
- **관측**: 로그 / 에러 / 알림 / 모니터링 / 통계(일부 중복)  
- **운영**: 유지보수  
- **규정**: 감사  

레이아웃: `AdminHeader`가 **전체 폭 상단**, 그 아래 `Sidebar | main` — 사이드바에 브랜드가 있고 헤더에도 “관리”가 있어 **이중 크롬**. 모바일에서 사이드바 고정 `w-64` → 본문 압박.

### 1.3 시각

- 토큰·Pretendard/SUITE·랜딩 히어로: ✅  
- 대시보드/Admin 본문: 동일 Card 타이틀 패턴 반복, 섹션 구분선·sticky 필터 외 계층 약함  
- Admin 페이지 타이틀 `text-3xl font-bold` vs 메인 `font-display text-brand-ink` — **타이포 계열 불일치**

## 2. 메뉴(IA) 제안

### 2.1 메인 헤더 — 소폭 보강 (권고)

| 변경 | 내용 | 이유 |
|------|------|------|
| M1 | 네비에 **업로드** 추가 (또는 `데이터` 그룹: 업로드) | 입구를 1급 목적지로 |
| M2 | 활성 데이터 배지 클릭 → 업로드/초기화 안내 | “N명 로드됨”이 장식에 그치지 않게 |
| M3 | (선택) 샘플 모드일 때 `샘플` 칩 | 실데이터와 혼동 방지 |
| M4 | 모바일: 하단 4탭(대시보드·지도·전략·더보기) **또는** 현 햄버거에 업로드 고정 | lg 미만 스캔성 |

**비권고**: 헤더에 전략 하위 7탭을 올리지 말 것 — 과밀.

### 2.2 전략 페이지 — 탭 → 세그먼트/셀렉트

현재 7개 `TabsTrigger`는 `text-xs`로 때움.

| 옵션 | 내용 | 추천 |
|------|------|------|
| **S-A** | `md+` 가로 탭 유지, `sm`에서는 Select로 전환 | ✅ 기본 |
| S-B | 좌측 서브네비 (전략 전용) | 중침습, 대시보드와 패턴 갈라짐 |
| S-C | 7→5 재병합 (이미 v5.2에서 축소함) | 추가 축소는 신중 |

### 2.3 Admin 사이드바 — **그룹화** (최우선 IA)

```
개요
  · 대시보드
  · 모니터링          ← 헬스 요약 (슬림)

사용자
  · 사용자 관리

관측
  · 로그 분석
  · 에러 로그
  · 시스템 알림
  · 통계              ← 사용자/세션 메타 (IP는 로그로 유도됨)

운영
  · 유지보수
  · 감사 로그
```

| 변경 | 내용 |
|------|------|
| A1 | `nav`를 섹션 라벨(`text-[11px] uppercase tracking-wide text-white/40`) + 항목으로 재구성 |
| A2 | 기본 랜딩 빠른액션을 그룹과 동일 순서로 |
| A3 | (선택) 에러·알림에 **미해결 뱃지** (숫자) — 관측 우선순위 |
| A4 | 통계와 로그 중복 문구를 사이드바 툴팁/설명으로 구분 (“사용자·세션” vs “IP·이상탐지”) |

**합치기 후보 (선택, 별도 승인)**: 모니터링을 대시보드 홈 상단 스트립으로 흡수하고 메뉴에서 제거 → 항목 8→7.

### 2.4 Admin 셸 레이아웃

| 변경 | 내용 |
|------|------|
| L1 | **Sidebar 좌측 풀하이트** + 그 오른쪽만 Header+main (표준 어드민) |
| L2 | Header에서 중복 브랜드 제거, 페이지 타이틀/브레드크럼만 |
| L3 | `md` 미만: 사이드바 드로어 + 햄버거 (메인 Header 패턴 재사용) |
| L4 | main `max-w-6xl` 또는 `max-w-7xl`로 읽기 폭 제한 (초광폭 카드 나열 완화) |

## 3. 디자인(시각) 제안 — Harbor 유지

### 3.1 타이포·페이지 크롬 통일

| ID | 제안 | 성공 기준 |
|----|------|-----------|
| V1 | Admin `h1`을 `font-display text-brand-ink`로 메인과 통일 | Admin/메인 제목 계열 동일 |
| V2 | 페이지 부제 `text-muted-foreground` 한 줄 패턴 공용 컴포넌트 `PageHeader` | 복붙 h1 제거 |
| V3 | KPI는 Card 대신 **메트릭 스트립**(보더리스, 구분선) — 대시보드·Admin 홈 | 카드 중첩 감소 |

### 3.2 대시보드 스캔성

| ID | 제안 |
|----|------|
| V4 | 섹션 앵커 네비(질병·지도·추세·수술·표) sticky 미니 링크 — 첫 뷰포트는 KPI+필터만 |
| V5 | 필터 패널 sticky + 배경 `bg-card/90 backdrop-blur` 유지, 적용 중 필터 칩 한 줄 |
| V6 | 차트 CardTitle을 “무엇을 보는가” 동사/명사 통일 (예: “질병 Top 10”, “월별 재방문”) |

### 3.3 랜딩·모션

| ID | 제안 |
|----|------|
| V7 | 히어로에 **실제품 앵커** 1장(대시보드/지도 스크린 스틸) — 추상 SVG만으로는 약함 (디자인 규칙: Real visual anchor) |
| V8 | 기존 fade-up 유지 + 스크롤 시 헤더 축소 1개 — 모션 예산 2–3개 준수, reduced-motion 유지 |
| V9 | CTA 그룹은 지금처럼 1개 primary + 1 text link 유지 (pill 클러스터 금지) |

### 3.4 Admin 본문

| ID | 제안 |
|----|------|
| V10 | 통계/로그 차트 색을 `chart-1…5` CSS 변수만 사용 (하드코딩 `#0088FE` 제거) |
| V11 | 테이블 페이지: 툴바(검색·필터·내보내기)를 한 줄 패턴으로 공용화 |
| V12 | 빈 상태: 일러스트 대신 한 문장 + 다음 행동 링크 (예: 알림 0건 → 로그 분석) |

### 3.5 명시적 비목표

- 다크모드 기본화, 퍼플 그라데이션, 글로우, rounded-full 뱃지 남발  
- Admin을 마케팅 랜딩처럼 풀블리드 히어로화  
- 차트 라이브러리 교체(Recharts 유지)

## 5. 우선순위·의사결정

```
Phase U (Admin 메뉴·셸) → Phase N (메인 네비·전략) → Phase V (폴리시)
```

**Executor 착수 전 선택지**

1. **Admin 모니터링 메뉴**: 유지(그룹 ‘개요’) vs 대시보드 흡수 후 메뉴 제거  
2. **메인 업로드**: 네비 항목 추가 vs CTA만 유지+모바일 고정  
3. **랜딩 스틸**: 스크린샷 추가 vs SVG 분위기만 유지  
4. **범위**: U만 / U+N / 전부(U+N+V)

**기본 권고**: 모니터링 유지(개요 그룹), 업로드 네비 추가, 랜딩 스틸 추가, 범위 **U → N → V** 순차.
